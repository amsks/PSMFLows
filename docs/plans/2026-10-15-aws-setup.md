# aws setup for PSMFlows (match the kisski stack)

Every step below is derived from the repo at commit 9eacf71 (`feat/inversion-integration`) and from the
kisski venv. Lines marked "unverified" were not run on an aws box. `requirements-kisski.txt` at the repo root
is `uv pip freeze` of the kisski venv (112 packages) and is the parity source.

## 3. Clone and create the venv

```bash
git clone https://github.com/amsks/PSMFLows.git ~/git/PSMFLows && cd ~/git/PSMFLows
git checkout feat/inversion-integration
curl -LsSf https://astral.sh/uv/install.sh | sh   # uv; kisski used 0.7.18
uv python install 3.11.13
uv venv --python 3.11.13 .venv
uv pip install --python .venv/bin/python -r requirements-kisski.txt
.venv/bin/python -c "import jax, mujoco, importlib.metadata as m; print(jax.__version__, mujoco.__version__, m.version('ogbench'), jax.devices())"
```

Expected: `0.7.1 3.12.0 1.1.0 [CudaDevice(id=0)]`. If a freeze pin fails to resolve, install the table-1
versions by hand (`"jax[cuda12]==0.7.1"` for the jax trio) and report the difference in the mailbox.

## 4. Environment variables (put in `~/.bashrc`)

```bash
export PSM_REPO=$HOME/git/PSMFLows
export PSM_DATA=/data/psmflows          # big disk: flow ~60 MB, cube preimages 320 MB, checkpoints 56 MB each
export OGBENCH_DATASET_DIR=$HOME/.ogbench/data
export MUJOCO_GL=egl
export XLA_PYTHON_CLIENT_PREALLOCATE=false
export HF_TOKEN=hf_...                  # read token for amsks/psmflows-preimages (private); write token to post
mkdir -p $PSM_DATA/logs $PSM_DATA/exp
```

OGBench ignores `OGBENCH_DATASET_DIR`: `envs/env_utils.py:make_env_and_datasets` calls
`ogbench.make_env_and_datasets(env_name)` without a `dataset_dir`, so datasets always land in
`~/.ogbench/data` (ogbench 1.1.0 `DEFAULT_DATASET_DIR`). Only a few `tools/diag_*.py` read the variable.
If the home disk is small, symlink `~/.ogbench/data` to the big disk. cube-single-play needs
`cube-single-play-v0.npz` (257 MB) and `cube-single-play-v0-val.npz` (26 MB); they download on the first
`make_env_and_datasets` call. To pre-download:

```bash
.venv/bin/python -c "import ogbench; ogbench.download_datasets(['cube-single-play-v0'])"
```

## 6. No SLURM: run the python commands directly in tmux

Every file under `scripts/slurm/`, `scripts/campaign_2026-10/`, `scripts/launch_psmflow.sh`,
`scripts/slurm/launch_*.sh` and `scripts/audit/launch_measure_loss_ablations.sh` calls `sbatch` or `srun`.
`scripts/eval500.sh` and `tools/eval_checkpoint.py` do not. `scripts/slurm/eval500.sbatch` only exports
`FLOW_DIR`, `PRE_NPZ`, `EVAL_LOGS`, `EVAL_WORKERS=4`, `MEM_FRAC=0.90` and calls `eval500.sh`; set those
yourself. `eval500.sh` defaults are the midi-01 paths, so always export `PSM_REPO`, `FLOW_DIR`, `PRE_NPZ`,
`EVAL_LOGS`. The five-task protocol is one `eval500.sh` call per `ENV_NAME=cube-single-play-singletask-task{1..5}-v0`
(what `eval500_packed.sbatch` loops over); the only readout that counts for `fbc3_pt` is `hgoal_each`:

```bash
tmux new -s eval
cd $PSM_REPO; RUN=$PSM_DATA/runs/psmgoal_ja_fbc3_pt_cube/sd000_s_2522773.0.20261006_111542
export FLOW_DIR=$PSM_DATA/flow/cube-single-play PRE_NPZ=$PSM_DATA/preimages/cube-single-play.npz \
       EVAL_LOGS=$PSM_DATA/logs EVAL_WORKERS=4 MEM_FRAC=0.90 GPU=0
for t in 1 2 3 4 5; do
  ENV_NAME=cube-single-play-singletask-task${t}-v0 bash scripts/eval500.sh psmgoal cube $RUN \
    psmgoal_ja_fbc3_pt_cube_sd000_500000_hgoal_each_task${t} agent.coef_source=hgoal_each agent.acting=gpi
done
for t in 1 2 3 4 5; do   # BC control from the same flow
  ENV_NAME=cube-single-play-singletask-task${t}-v0 bash scripts/eval500.sh bc cube - bc_cube_task${t}
done
.venv/bin/python tools/make_tables.py --logs $PSM_DATA/logs
```

Stage C training, one seed per GPU (the CLAUDE.md command, `agent.use_point_preimage=true` as in README):

```bash
tmux new -s train_sd0
CUDA_VISIBLE_DEVICES=0 .venv/bin/python main.py agent=psmgoal env_name=cube-single-play-singletask-v0 \
  agent.flow_ckpt_path=$PSM_DATA/flow/cube-single-play agent.flow_ckpt_epoch=500000 \
  agent.preimage_path=$PSM_DATA/preimages/cube-single-play.npz agent.use_point_preimage=true \
  offline_steps=500000 eval_interval=50000 eval_episodes=50 save_dir=$PSM_DATA/exp seed=0
```

Smoke it first with `offline_steps=200 eval_interval=100 eval_episodes=1`, then read the run's own
`flags.json` under `$PSM_DATA/exp/` to confirm the values landed. `configs/config.yaml` sets
`wandb_entity: amsks`; pass `wandb_project`/`wandb_entity` or run `wandb offline` if that account is absent.

## 7. Verification checklist

1. xla_guard ordering (tests/conftest.py imports `utils.xla_guard` before any jax import):
   `.venv/bin/python -m pytest tests/test_xla_autotune_guard.py -x -q`
2. Agent unit tests, one file per process (the whole suite in one process aborts in XLA):
   `PSMFLOWS_STAGE_A_CKPT=$PSM_DATA/flow/cube-single-play .venv/bin/python -m pytest tests/test_psmflow_agent.py -x -q`
   and `.venv/bin/python -m pytest tests/test_psmgoal.py -x -q`, `tests/test_eval_checkpoint_flags.py`.
   Expected: pass; the Stage-A test runs instead of skipping once the variable points at the pulled flow.
3. One-episode eval of the pulled checkpoint (dataset download happens here on first run):
   ```bash
   MUJOCO_GL=egl .venv/bin/python tools/eval_checkpoint.py agent=psmgoal env_name=cube-single-play-singletask-task1-v0 \
     agent.flow_ckpt_path=$PSM_DATA/flow/cube-single-play agent.flow_ckpt_epoch=500000 \
     agent.preimage_path=$PSM_DATA/preimages/cube-single-play.npz agent.use_point_preimage=true \
     agent.coef_source=hgoal_each agent.acting=gpi restore_path=$RUN restore_epoch=500000 \
     eval_episodes=1 report_out=$PSM_DATA/logs/smoke_task1.json
   ```
   Expected: no error, `agent config defaults from .../flags.json` printed, a JSON with a `success` field.
4. Parity (the check luis did on 2026-10-09 with `EVAL_WORKERS=4`, `hgoal_each`, 500 episodes per task):
   same checkpoint, same eval seed (unset, so config default 0), GPUs differ in float bits, so expect agreement
   within about 0.01 on the five-task mean and within binomial noise per task (luis vs kisski at 250k: 0.826 vs
   0.818). kisski reference for `fbc3_pt` sd000 `params_500000`, `hgoal_each`, 500 episodes per task:

   | task 1 | task 2 | task 3 | task 4 | task 5 | five-task mean |
   |---|---|---|---|---|---|
   | 0.696 | 0.796 | 0.960 | 0.736 | 0.594 | 0.756 |

   Five-seed mean of the arm at 500k is 0.805; BC control (frozen flow alone) is 0.11 on the same protocol.
   `EVAL_WORKERS=1` reproduces a kisski N=1 number bit for bit on the same GPU class only; N=4 draws a
   different 500-episode sample and agrees within the Wilson interval.
5. Post the parity table to `mailbox/aws/` with `from: aws` front matter before launching any arm.
