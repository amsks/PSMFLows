## Definition

PSMFlows-2P is a two-phase recipe on the frozen behaviour flow.

- Phase 1 trains the default affine agent end to end (phi and psi together).
- Phase 2 loads phi from a phase-1 checkpoint, holds it fixed, re-initialises psi and trains psi from scratch.
- Phase-2 flags: `agent.phi_restore_path=<phase-1 run dir>`, `agent.phi_restore_epoch=<step>`, `agent.train_phi=false`.
- Phase 2 reads only the online phi parameters from the checkpoint. It does not read phi's optimiser state, psi or anything else.

Two phase-2 variants exist.

- **PSMFlows-2P-GPI.** The flags are the `cube_frozen_own_phi_gpi` template: `psi_form=affine`, `policy_index=latent`, `acting=gpi`, `u_clip=3.0`. Only the phi restore keys, steps, group and seed differ.
- **PSMFlows-2P-DSRL.** The same template plus these flags: `agent.policy_index=task_vector agent.train_actor=true agent.acting=actor agent.actor_mode=dsrl_sac agent.actor.bc_coeff=0.0 agent.actor.target_entropy=-3.4657`.
  - The DSRL-SAC actor settings are the yaml defaults: `entropy=auto`, `init_alpha=1.0`, `lr_alpha=3e-4`, `lr_actor=1e-4`, `q_coeff=1.0`.
  - The actor critic is psi read through the task vector. `dsrl_na` is off.

### Why the DSRL variant keeps `u_clip=3.0`

`u_clip` sets the tanh scale of the DSRL actor's output. The same key also clips the dataset preimages `u_data`, the backup latents and the candidate latents that psi trains on (`agents/psmflow.py` sample_step_inputs and the TD target). `index_clip` bounds only the policy-index draws u'. Under `policy_index=task_vector` the index slot carries w, so `index_clip` has no effect. No key bounds only the actor's output.

Setting `u_clip=1.5` would therefore change psi's training data between the two variants. It would also change it relative to the phase-1 basis, which was trained at 3.0. Fraction of the cube dataset's 1M point preimages (`noise_preimage_point`) outside each box:

| box | rows with any \|u_i\| above the box | entries above the box |
|---|---|---|
| 1.5 | 0.576 | 0.157 |
| 3.0 | 0.022 | 0.0044 |

The DSRL variant uses `u_clip=3.0` and the corrected entropy target for a 3.0 box.

    target_entropy = -d_a * log(3.0 / 1.5) = -5 * log 2 = -3.4657

This is the value the corrected SAC arm `affine_dsrl_sac_te_cube` used (`docs/design/2026-09-06-dsrl-actor-audit.md` §4f). The first DSRL CPU smoke ran at `u_clip=1.5`, target 0.0. It was replaced before any phase-2 DSRL run launched.

## Eval grid

- Each phase-2 run is evaluated at psi steps 50k, 100k, 250k, 500k, 1M, 2M and 3M: 24 × 7 × 5 = 840 jobs. OUT is `<group>_sd00{k}_{step}_task{t}`.

## Pre-registered readings for the schedule

1. At a fixed psi step, if the five-task mean rises with basis age (500k → 1M → 1.5M → 2M), then basis training length matters.
2. If the five-task mean falls with psi steps inside a phase-2 run, then psi needs a stopping rule that does not use the test reward. `td_target_absmean` and `psm_loss` from train.csv will be tabulated at every eval-grid step as candidate signals.
3. If 2P-DSRL scores above 2P-GPI at a matched basis and psi step, then the policy step was limiting, and the measure was not. If 2P-DSRL scores below 2P-GPI, then the measure's action-axis readout limits the actor as well.

Expected outcomes, stated before results:
- The 50k-to-150k dip seen in task A will recur in the 2P-GPI runs at every basis age.
- 2P-DSRL will score at or below 2P-GPI. Every measure-as-critic actor arm on cube so far has scored 0.04-0.23 five-task.

A CPU smoke of `restore_path` continuation (group `affine_strict_cube_to1M_cpusmoke`) showed that a restore carries the Adam state.
